Any file showing as **imported** has a **Play** icon in the Downloads list of
its show/movie detail page.

## Playback

Click **Play** to open the video player dialog. The player uses this fallback
sequence:

1. **Direct stream** — the original file over HTTP range requests so you can
   seek immediately.
2. **Browser-side remux/re-encode** — when native playback fails or the file
   needs conversion (for example a Matroska container or audio codecs the
   browser won't decode, such as AC3), Mediabunny remuxes or re-encodes via
   **WebCodecs** when `VideoDecoder` and `AudioDecoder` are available.
3. **Download** — fetch the raw file when WebCodecs isn't available or
   playback still fails.

When WebCodecs is missing, the error reads **"This browser cannot play this
file."** Use the **Download File** button (shown on error and in the dialog
footer) and play locally.

<Callout type="info">

**Server-side transcoding (optional).** For containers outside MP4, M4V, WebM,
and MOV, the API may offer a cached HLS rendition (H.264/AAC) when `ffmpeg` is
installed. Safari can play that playlist natively; other browsers remux it
through Mediabunny without re-encoding on the client. That path is separate
from the browser-side fallback in step 2 above.

</Callout>

## Subtitles

Each fetched subtitle language appears as a selectable track in the player.
`.srt` is converted to WebVTT on the fly so browsers accept it. Manage which
languages are fetched in [Subtitles](/docs/configuration/subtitles), or pull
them on demand with the subtitle-search button on the detail page. Language
badges on season/movie pages show what's available.

The player footer also has a **Download** button for the raw file — useful
for files your browser can't decode, or just for offline copies.

<Callout type="info">

Playback depends on your browser, container, and codecs. For files that still
won't play in-browser, download and use a desktop player instead.

</Callout>
