MiraMedia can check GitHub for new releases and notify you when a newer version
is available. **Applying** an update is done on the host with Docker Compose —
in-app apply is not supported.

## Settings (`[updates]`)

- `enabled` — run the periodic check. Default `true`.
- `repo` — GitHub `owner/repo` for the releases API. Default
  `miramedia-app/miramedia`.
- `check_interval_hours` — default `24`.
- `include_prereleases` — default `false` (stable only).
- `cache_ttl_seconds` — cache the release check result. Default `3600`.
- `request_timeout_seconds` — HTTP timeout for the GitHub releases call.
  Default `10`.
- `notify_on_new_version` — send a notification when a newer version is
  found. Default `false`. Uses your configured
  [notification providers](notifications).
- `image_repository` / `image_tag` — used for the version endpoint display.
  Default `ghcr.io/miramedia-app/miramedia` and `latest`.

### Applying updates on the host

When a new release is available, pull and recreate the stack on the host:

```sh
docker compose pull && docker compose up -d
```

<Callout type="info">

Legacy keys such as `allow_in_app_apply`, `docker_socket_path`, and
`container_name` may still appear in older `config.toml` files. They are
ignored at startup with a warning. Do not mount `/var/run/docker.sock` for
updates.

</Callout>

## Example

```toml title="config.toml"
[updates]
enabled = true
repo = "miramedia-app/miramedia"
check_interval_hours = 24
include_prereleases = false
notify_on_new_version = true
image_repository = "ghcr.io/miramedia-app/miramedia"
image_tag = "latest"
```

The current version is always visible via `GET /api/v1/system/version`.
Update checks are superuser-only.
